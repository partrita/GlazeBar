# ADR 0001: 상단바 2단계 투명도 고정, 흰색 폰트, 테두리 전용 작업공간 및 높이 조절 지원

- **상태 (Status)**: 승인됨 (Accepted)
- **일자 (Date)**: 2026-11-09
- **작성자**: Antigravity (grill-with-docs 세션)

---

## 1. 배경 및 맥락 (Context)
현재 GlazeBar의 상단바 투명도는 100%, 80%, 60%, 40%, 20%, 0%의 6단계 퍼센트 단계로 분할되어 있습니다.
그러나 실제 사용 시 중간 투명도(80~20%)는 텍스트 가독성 저하와 백그라운드 색상 왜곡을 유발하며, 0%(완전 투명) 설정 시에도 작업공간(Workspace) 영역이 `ui.surface` 및 `ui.selected` 배경 채우기로 인해 불투명한 회색 박스로 남아 디자인 완성도를 저해합니다.
또한 상단바 높이가 `40. * scale`로 하드코딩되어 있어 고해상도 디스플레이나 소형 랩톱 화면에서 사용자가 원하는 높이로 커스터마이징할 수 없는 제약이 있습니다.

## 2. 의사결정 동인 (Decision Drivers)
- **단순성과 직관성**: 불필요한 중간 단계 투명도를 없애고 "불투명"과 "투명" 2가지로 명확히 선택 가능해야 함.
- **가독성 보장**: 투명 모드일 때 바탕화면 이미지와 상관없이 텍스트와 아이콘이 또렷하게 보이도록 순백색(`0xFFFFFF`)으로 고정.
- **일관된 투명 UI**: 작업공간 버튼의 배경 면 채우기를 제거하고 테두리선(Border-only)으로만 표현하여 투명한 외형 완성.
- **유연한 화면 활용**: 사용자의 디스플레이 환경과 취향에 맞게 상단바 높이를 32px ~ 48px 범위에서 조절할 수 있도록 설정 항목 제공.
- **무결성 및 안정성**: 설정 변경 시 윈도우 AppBar 재배치 및 실시간 저장이 원활하게 이루어져야 함.

## 3. 검토된 대안들 (Considered Options)
1. **투명도 단계**:
   - 대안 A: 기존 6단계 유지
   - 대안 B: 슬라이더(0~100%) 방식
   - 대안 C (채택안): `[불투명 (100%), 투명 (0%)]` 2단계 세그먼트
2. **투명 모드 글자색**:
   - 대안 A: 테마별 글자색 유지 (어두운 테마 시 가독성 훼손)
   - 대안 B (채택안): 순백색(`0xFFFFFF`) 고정
3. **작업공간 표시**:
   - 대안 A: 불투명 모드/투명 모드 모두 테두리 전용으로 통일
   - 대안 B (채택안): 투명 모드에서는 테두리 전용으로 렌더링하고, 불투명 모드에서는 기존 테마 면 채우기 유지
4. **상단바 높이 조절**:
   - 대안 A: 임의의 픽셀 입력
   - 대안 B (채택안): 5단계 프리셋 `[32px (슬림), 36px (조밀), 40px (기본), 44px (넉넉), 48px (큼직)]` 세그먼트 버튼 제공

## 4. 최종 확정된 결정 (Decision Outcome)
사용자와의 Grilling 인터뷰를 거쳐 5개 질문에 대해 만장일치로 합의되었습니다:
1. **투명도 단계**: `OPACITY_STEPS`를 `[("불투명", 100), ("투명", 0)]` 2단계로 단순화.
2. **글자 및 아이콘 색상**: 투명 모드 활성화 시 상단바의 모든 텍스트와 시스템 위젯 아이콘을 순백색(`0x00FFFFFF`)으로 일괄 고정.
3. **작업공간 렌더링**: 투명 모드에서는 면 채우기(`c.fill`)를 제거하고 테두리(`c.frame`)로만 박스 영역을 그리며, 활성(Focused/Displayed) 작업공간은 또렷한 흰색 2px 테두리로, 비활성 작업공간은 은은한 테두리로 구분.
4. **적용 범위**: 불투명 모드에서는 기존 테마의 면 채우기 스타일을 유지하고, 투명 모드에서만 테두리 전용 스타일 적용.
5. **상단바 높이 조절**: `BarSettings`에 `bar_height_idx`를 추가하고 5개 프리셋(32, 36, 40, 44, 48px)을 제공하며, 변경 즉시 실시간 AppBar 크기 및 GlazeWM 작업영역 재배치 적용.
